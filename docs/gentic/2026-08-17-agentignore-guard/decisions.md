# Decisions: agentignore-guard

| Decision | Chosen | Alternatives considered | Why | Source |
|----------|--------|------------------------|-----|--------|
| Enforcement scope | `Read`, `Edit`, `Write`, `NotebookEdit`, plus a path scan of `Bash` commands. `Grep`/`Glob` left unguarded. | (A) file tools only; (B) also filter Grep/Glob output | Guarding `Read` alone is illusory — `cat .env` bypasses it. Scanning Bash closes the obvious hole. Filtering Grep output means rewriting tool results and hiding matches confusingly, for a gap that is documented instead. | user |
| File format | Bare patterns deny read **and** write. `[read-only]` allows read, denies write. `[no-read]` denies read, allows write. `!pattern` re-allows both. Last matching rule wins. | (B) per-line prefixes; (C) bare = read-only | Preserves `.cursorignore` muscle memory (the user already authors these) and keeps the strict reading for a bare listing, which is what someone writing `secrets/` means. | user |
| Response to a hit | Hard `permissionDecision: "deny"` naming the rule and the file that produced it. | (B) escalate to a prompt; (C) deny writes, escalate reads | "Not allowed" was the user's phrasing. A prompt on every hit becomes noise that gets click-approved. Editing `.agentignore` is the escape hatch. | user |
| Discovery | Every `.agentignore` from the target file's directory up to the repo root (or filesystem root outside a repo), combined outermost-first so inner files win. | (B) repo root only; (C) cwd only | Matches gitignore intuition and lets a subfolder protect itself — the "files in a specific folder" framing in the request. | default — unconfirmed |
| Negation | `!pattern` supported, gitignore-style. | No negation | Without it, protecting `secrets/` while exposing `secrets/README.md` is impossible. | default — unconfirmed |
| Off-switch | None. The guard always applies; access is changed by editing `.agentignore`. | An `AGENTIGNORE_OFF` env var | A documented off-switch that the model can read is not a guard. | default — unconfirmed |
| Failure posture | Fail **open**: an unreadable or malformed `.agentignore` warns via `systemMessage` and allows the call. | Fail closed (deny on parse error) | Consistent with the layer's founding rule that a hook must never break a session; failing closed on a typo would block every file operation in a repo. Documented as an explicit limitation. | default — unconfirmed |
| Security framing | Documented as an **accident-preventer, not a security boundary**. | Presenting it as enforcement | `Grep`/`Glob` remain unguarded, Bash scanning is heuristic, and the model could construct paths dynamically. Overstating it would be the more dangerous outcome. | default — unconfirmed |
| Implementation site | Extend the existing `pre_tool_use.py` rather than adding a second `PreToolUse` hook. | A separate hook script | One matcher entry, one process spawn per tool call, and the destructive-git guard already owns this event. | default — unconfirmed |
