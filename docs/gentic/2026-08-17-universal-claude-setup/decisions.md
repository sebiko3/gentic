# Decisions: universal-claude-setup

| Decision | Chosen | Alternatives considered | Why | Source |
|----------|--------|------------------------|-----|--------|
| Git/GitHub autonomy | Nothing git-related fires unprompted. A single `/ship` command runs the whole sequence unattended: work branch → checkpoint commits → verification → PR body → push → open PR. | (B) auto-commit on work branches with push/PR gated; (C) fully automatic end to end | Preserves `~/.claude/CLAUDE.md`'s "do not commit, push, create pull requests … unless explicitly asked" verbatim — no amendment needed. The user gets full automation *inside* an explicit invocation, which is the automation they wanted without surrendering the control their own contract protects. | user |
| Spec engine | Promote gentic to global (`~/.claude/skills/`), calling superpowers skills at its existing composition points. | (B) drive superpowers brainstorming → writing-plans → executing-plans directly; (C) route by task size between both | gentic already encodes phases, gates, durable artifacts and resume; superpowers plans live only in context. One engine avoids the fourth-competing-system failure mode already visible across superpowers/gentic/sheldon. | user |
| Enforcement strength | Advisory context injection for routing/intent; hard `exit 2` blocks reserved for objectively checkable conditions only (done-claim with no verification run, unchecked DoD items, protected-path edits). | (B) advisory only; (C) aggressive hard-blocking | Blocking on a judgement call ("is this non-trivial?") creates deadlocks with no user escape. Blocking on a checkable fact is safe and is the specific leverage hooks add over skills. Advisory-only reproduces the exact discipline gap that prompted the request. | user |
| Packaging | Directly in `~/.claude/` — `settings.json` hooks + `skills/` + `agents/` + `commands/`. | (B) personal plugin in the `sheldon` marketplace; (C) `~/.claude/` now, extract to a plugin later | Global the moment it is written, with no marketplace cycle or enable step; those three directories are currently empty. Plugin extraction remains available later without rework. | user |
| Intent classification | Deterministic script on `UserPromptSubmit` (prompt shape + repo state heuristics). No LLM call on the per-prompt hot path. | (A) `type: "agent"`/`"prompt"` LLM hook; (C) always inject the routing rule unconditionally | `UserPromptSubmit` fires on every prompt; an LLM hook there taxes every turn with latency and tokens. The routing conditions in `CLAUDE.md` are already expressed as checkable predicates. Escalate to an LLM hook only if the heuristic measurably misroutes. | default — unconfirmed |
| Verification gate | `Stop` hook blocks (`exit 2`) only when the response claims done/fixed/passing **and** no verification command ran that turn. | (A) run the project test suite on every Stop; (C) advisory reminder only | (A) is far too slow and fires on purely conversational turns. (B) targets precisely the failure being eliminated and gives `verification-before-completion` actual teeth. | default — unconfirmed |
| Artifact location | `docs/gentic/<date>-<slug>/` committed, as today — with an opt-out for repos where adding files is unwelcome, falling back to `~/.claude/gentic-runs/<project>/`. | (A) always in-repo; (B) always outside the repo | Keeps the existing committed-documentation convention where it fits, without forcing artifacts into repos the user does not own. | default — unconfirmed |
| Reuse of installed official plugins | Enable `pr-review-toolkit` only, and orchestrate its review agents from the verify stage. | (A) also enable `feature-dev`; (C) enable none and write equivalents | Its six review agents are directly reusable and are not duplicated anywhere in the stack. `feature-dev` would duplicate gentic's phases and reintroduce the competing-engine problem. | default — unconfirmed |
| Prompt transformation mechanism | Context injection alongside the prompt (exit-0 stdout on `UserPromptSubmit`). | Literal prompt rewriting via `hookSpecificOutput.updatedPrompt` | Forced by the platform, not chosen: `updatedPrompt` returns zero matches in the installed 2.1.193 binary while `updatedInput` returns 227. Rewriting is not available in this build. | default — unconfirmed (platform-forced) |
| Failure posture of hooks | Every hook always exits 0 on its own errors, surfacing problems via `systemMessage`; only deliberate policy blocks use exit 2. | Let hook errors propagate | A broken hook must never be able to brick every session in every project. This is Anthropic's own reference shape in `hookify`. | default — unconfirmed |
